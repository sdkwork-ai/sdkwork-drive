## 存储中心 Admin 完善方案

### 概念模型
- **服务商（ProviderKind）**：内置 7 个（local_filesystem / s3_compatible / google_cloud_storage / aliyun_oss / tencent_cos / huawei_obs / volcengine_tos），注册表存于新表，可开启/关闭；`custom:*` 视为始终可用的用户自定义服务商
- **配置（Provider）**：现有 `dr_drive_storage_provider` 行 = 某服务商下的一个配置（endpoint/region/凭据/桶）；一个服务商可有多个配置（现结构已支持，前端补充按服务商过滤/统计）
- **存储桶（Bucket）**：隶属于某个配置；管理界面用下拉列表（按服务商分组 optgroup）选择配置
- **禁用语义**：关闭服务商后禁止新建/编辑/重新激活其配置，存量 active 配置仍可正常使用

### 1. 数据库
- 迁移 `0008_drive_storage_provider_kind.up.sql`：新建 `dr_drive_storage_provider_kind`（provider_kind PK、display_name、enabled、sort_order、version、时间戳），并 INSERT 初始化 7 个内置服务商（ON CONFLICT DO NOTHING，即"初始化配置"）；配套 down.sql；更新 `metadata.json`
- 同步契约：`pnpm db:materialize:contract` 重新生成 schema.yaml/table-registry.json，`pnpm db:validate` 校验

### 2. 后端 Rust（workspace-service + routes crate）
- 新增 `domain/storage_provider_kind.rs`、`ports/storage_provider_kind_store.rs`、`infrastructure/sql/storage_provider_kind_store.rs`（含 entity）、`application/storage_provider_kind_service.rs`：
  - `initialize_storage_provider_kinds`（幂等 upsert，可随时重新初始化）
  - `list_storage_provider_kinds` / `set_storage_provider_kind_enabled`

- `storage_provider_service.rs`：create / update / status→active 时组合校验服务商存在且开启（路由层调用 kind service）
- 新路由（`route_paths.rs` + `provider_kind_handlers.rs` + `dto.rs` + mappers + `handlers.rs` re-export）：
  - `GET /drive/storage/provider-kinds`（list，含配置数）

- contract `domain_events.rs` 增加 audit 事件：`drive.storage_provider_kind.initialized/enabled/disabled`；`audit.rs` 增加记录辅助
- 测试：`storage_provider_kind_service.rs`（初始化幂等、开关、custom 放行）+ routes 测试（kinds 路由、禁用后创建配置被拒）
